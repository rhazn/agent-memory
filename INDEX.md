# Shared Memory

This private repository maintains continuity of understanding across all agents,
models, and environments. It is not a task log or workflow database.

## Baseline

Read these short documents at the start of a session, then use their context:

- [About Philip](ABOUT.md): personal and professional background.
- [Working together](WORKING-TOGETHER.md): collaboration and memory approval.
- [Shared soul](SOUL.md): collaborator identity, independent judgment, and pragmatism.

## Read When Relevant

- [Isselthal](about/isselthal.md): company context, ownership, and public references.
- [Writing](working-together/writing.md): editing prose, especially lint fixes.
- [Coding](working-together/coding.md): implementation scope and dependency choices.
- [Business development](working-together/business-development.md): assessing
  engagements, locations, expertise, and interview requirements.
- [Engagement opportunities](working-together/engagement-opportunities.md): audience, selection, and comment preferences.

Read the relevant detail before asking Philip for information already recorded.
Do not load every detail file for unrelated tasks. Add further detail files only
when meaningful approved context needs them, not to complete a template.

## Maintenance

Propose meaningful learning; do not manufacture updates. Show the exact proposed
wording, destination, and any replacement or deletion. Wait for explicit approval
before changing memory. Approval covers staging, committing, and pushing the
agreed changes in this repository, not unrelated changes or other repositories.

Revise existing understanding rather than accumulating duplicate rules. Keep
confirmed facts distinct from tentative interpretations. Never record credentials
or unnecessary sensitive information. Keep implementation history, session
summaries, test counts, and workflow checkpoints out of this repository.

Use the `agent-memory` skill for checkout locations and synchronization rules.
